# Визуализатор зависимостей Maven — вариант №25

## Общее описание

Реализован **только этап 1**: минимальное CLI-приложение на Python,
которое читает XML, проверяет настройки и выводит их в формате
`ключ=значение`. Используется исключительно стандартная библиотека.
Получение зависимостей, обход графа и визуализация относятся к следующим
этапам и пока не реализованы. Сетевые запросы не выполняются.

## Требования и структура

Нужен Python 3.10 или новее. Устанавливать зависимости и собирать проект
не требуется. `run.sh` предназначен для POSIX shell; на Windows можно
запускать Python напрямую.

```text
src/dependency_visualizer/   исходный код
tests/                      тесты unittest
examples/                   XML и тестовый файл
run.sh                      запуск из любого каталога
README.md                   документация
.gitignore                  исключения для Git
```

## Запуск и тесты

Из корня проекта:

```sh
sh run.sh --help
sh run.sh --config examples/maven.xml
sh run.sh --config examples/test.xml
PYTHONPATH=src python3 -m unittest discover -s tests -v
```

Прямой запуск модуля:

```sh
PYTHONPATH=src python3 -m dependency_visualizer --config examples/maven.xml
```

В PowerShell:

```powershell
$env:PYTHONPATH = "src"
python -m dependency_visualizer --config examples/maven.xml
python -m unittest discover -s tests -v
```

## Все настройки

Единственный источник четырех пользовательских параметров — XML-файл.
Аргумент `--config` обязателен и выбирает этот файл; переопределения
параметров через CLI или переменные окружения нет.

```xml
<?xml version="1.0" encoding="UTF-8"?>
<configuration>
    <package>org.apache.commons:commons-lang3</package>
    <repository>https://repo.maven.apache.org/maven2</repository>
    <test_mode>false</test_mode>
    <version>3.14.0</version>
</configuration>
```

| Параметр | Правила |
| --- | --- |
| `package` | В обычном режиме `groupId:artifactId`; в тестовом — буквы A–Z. |
| `repository` | При `false` — HTTP(S) URL; при `true` — читаемый обычный файл. |
| `test_mode` | Только `true` или `false`, с учетом регистра. |
| `version` | Явная версия: латинские буквы, цифры, `.`, `_`, `+`, `-`. |

Части Maven-имени состоят из латинских букв, цифр и `_`, разделенных
одиночными `.` или `-`. Пустые части, пробелы и дополнительные `:`
запрещены. Версия начинается с буквы или цифры; диапазоны не поддерживаются.
Это синтаксическая проверка: существование пакета и версии пока не проверяется.

URL должен содержать хост и допустимый порт, если порт указан.
Запрещены пробелы, обратный слеш, учетные данные, query и fragment.
Доступность сервера не проверяется.

Относительный путь репозитория отсчитывается **от каталога XML-файла**.
В выводе он нормализуется до абсолютного пути. Содержимое тестового файла
на этапе 1 не анализируется; `repository.txt` содержит пример для будущей
работы с графом, а не окончательную спецификацию его формата.

Все поля обязательны, порядок произвольный. Пробелы по краям значений
удаляются. Повторы, неизвестные поля, атрибуты, вложенные элементы,
посторонний текст, DTD и объявления сущностей запрещены. XML читается
в UTF-8, допускается BOM. Комментарии XML допускаются.

## Пример результата

```text
package=org.apache.commons:commons-lang3
repository=https://repo.maven.apache.org/maven2
test_mode=false
version=3.14.0
```

В тестовом режиме выводятся `package=A`, `test_mode=true`, `version=1.0`
и полный путь к `examples/repository.txt`.

## Демонстрация ошибок всех параметров

Каждую команду следует выполнять отдельно: ожидается код завершения `1`.

```sh
sh run.sh --config examples/invalid_package.xml
sh run.sh --config examples/invalid_repository.xml
sh run.sh --config examples/invalid_test_mode.xml
sh run.sh --config examples/invalid_version.xml
```

| Файл | Причина и фрагмент сообщения |
| --- | --- |
| `invalid_package.xml` | `package: ожидается groupId:artifactId.` |
| `invalid_repository.xml` | `repository: нужен HTTP(S) URL…` |
| `invalid_test_mode.xml` | `test_mode: допустимы только true и false.` |
| `invalid_version.xml` | `version: ожидается версия…` |

Полное сообщение начинается с `Ошибка конфигурации:` и идет в stderr.
При ошибке настройки в stdout не выводятся; показывается первая ошибка.
Коды: `0` — успех или справка, `1` — ошибка конфигурации, `2` — ошибка
аргументов командной строки (стандартное поведение argparse).

Тесты дополнительно проверяют отсутствие и пустоту каждого поля,
дублирование всех полей, сломанный XML, неверный корень, DTD,
неверную кодировку, отсутствующий XML, каталог вместо файла,
некорректные URL и тестовые имена, отказ доступа к тестовому файлу,
относительные пути, stdout, stderr и коды завершения.
Отказ доступа моделируется через mock, чтобы тест работал и от root.

## Функции и классы

| Модуль | Объект | Назначение |
| --- | --- | --- |
| `validation` | `ConfigError` | Исключение для ошибок конфигурации. |
| `validation` | `validate_package` | Проверка имени в выбранном режиме. |
| `validation` | `validate_version` | Проверка синтаксиса явной версии. |
| `validation` | `parse_test_mode` | Преобразование true/false в bool. |
| `validation` | `validate_url` | Проверка синтаксиса URL. |
| `validation` | `validate_repository` | Проверка URL либо доступности файла. |
| `config` | `Config` | Неизменяемый контейнер четырех настроек. |
| `config` | `read_xml` | Чтение UTF-8 XML и обработка ошибок файла. |
| `config` | `validate_root` | Проверка корня XML. |
| `config` | `read_field` | Проверка и чтение простого поля XML. |
| `config` | `extract_fields` | Проверка структуры XML и извлечение полей. |
| `config` | `load_config` | Сборка проверенной конфигурации. |
| `cli` | `create_parser` | Описание --config и справки. |
| `cli` | `main` | Запуск проверок, вывод результата и код возврата. |

Вспомогательные методы тестов `setUp`, `write_config` и `invoke`
создают временные данные, записывают XML и запускают CLI соответственно.
Остальные методы `test_*` документированы docstring и запускаются unittest.

## Оформление и история Git

Числовые коды завершения вынесены в именованные константы.
В исходном коде и тестах нет числовых литералов в сравнениях.
Вместо поясняющих комментариев используются docstring.
Python-строки ограничены 80 символами, функции — 40 строками.
Служебные файлы Python, настройки редакторов, архивы и результаты сборки
не включаются в коммит.

Этап сохраняется коммитом Conventional Commits со scope:

```text
feat(config): implement stage 1 XML CLI prototype
```

Архив проекта содержит каталог `.git` с историей этого этапа.
После распаковки историю можно проверить:

```sh
git log -1 --format=full
git status --short
```

Для публикации создайте пустой публичный репозиторий на выбранном сервисе,
затем из корня этого проекта выполните команды, подставив его адрес:

```sh
git remote add origin YOUR_REPOSITORY_URL
git push -u origin main
```

Публичная публикация требует адреса репозитория и доступа к нему.
